# TCP 24040 중계 서버로 교체하기

이 안내는 세 기기 모두 `10.255.81.76:24040`의 HTTP 테스트에 성공한 환경을 기준으로 합니다.
`10.255.81.76`은 사설 주소입니다. 외부 인터넷 기기에서는 별도로 연결이 확인된 공인 주소를 사용하세요.

## 무엇이 실행되는가

```text
방장 게임기 ── TCP ──┐
                    ├── 10.255.81.76:24040 중계 서버
상대 게임기 ── TCP ──┘
```

중계 서버는 방 생성·검색·두 기기의 메시지 전달을 담당합니다. 방장 기기가 기존 `Game` 규칙으로
착수, 승패, 스위칭 일정을 판정하고 상태를 공유합니다. 서버가 모든 게임을 판정하는 구조는 아닙니다.
기존 GPIO/LCD, 가위바위보, 모드 선택, 연출 완료 대기, 일시정지, 결과 기록을 그대로 사용합니다.

## 1. 수정 파일 전달

맥북의 이 프로젝트 폴더에서 업데이트 묶음을 만듭니다.

```bash
python3 tools/package_online.py
```

`dist/vttt-online-update.tar.gz`를 서버와 두 게임기에 전달합니다. USB로 복사해도 됩니다.
SSH로 전달한다면 아래 `SSH포트`, `계정`, `SSH주소`를 **현재 실제 SSH 접속에 쓰는 값**으로 바꿉니다.
게임 포트 24040을 SSH 포트 자리에 넣지 않습니다.

```text
scp -P SSH포트 dist/vttt-online-update.tar.gz 계정@SSH주소:~/
```

서버에서는 새 작업 폴더에 압축을 풀어도 됩니다. 중계 서버에는 Python 3.9 이상만 필요하며
Pillow, NumPy, GPIO 패키지, 모델, LCD 이미지는 필요하지 않습니다.

```bash
mkdir -p ~/vttt-online
tar -xzf ~/vttt-online-update.tar.gz -C ~/vttt-online
```

**게임기에서는 기존 게임 프로젝트 폴더를 현재 위치로 두고** 압축을 풉니다.
이 묶음은 업데이트용이므로 게임기에는 기존 전체 프로젝트와 실행 패키지들이 이미 있어야 합니다.
기존 파일을 교체하므로 수정한 코드가 있다면 먼저 별도로 보관하세요.
프로필, GPIO 핀 JSON, 학습 모델과 이미지는 묶음에 포함하지 않습니다.

```bash
tar -xzf ~/vttt-online-update.tar.gz
```

## 2. 기존 HTTP 테스트 서버 종료

서버에서 실행합니다.

```bash
sudo ss -ltnp | grep :24040
```

출력에 `python3`와 `pid=숫자`가 보이면 그 PID에 `kill`을 실행합니다.
예를 들어 PID가 12345라면 `kill 12345`입니다. `sshd`를 종료하지 마세요.
다시 조회해 24040의 LISTEN이 없어졌는지 확인합니다.

## 3. 중계 서버 실행

서버에서 다음을 실행합니다.

```bash
cd ~/vttt-online
python3 -u -m vttt.relay_server --bind 0.0.0.0 --port 24040
```

`VTTT relay listening on 0.0.0.0:24040`이 나오면 준비되었습니다.
처음에는 이 화면을 열어 둔 채로 게임기를 연결합니다.
방 생성 시 `Room 1234 created`, 두 기기 연결 시 `Room 1234 paired` 로그가 나옵니다.
오류 `Address already in use`는 기존 프로그램이 같은 포트를 사용 중이라는 뜻입니다.

백그라운드로 실행하려면 먼저 Ctrl+C로 전면 실행을 종료한 다음 아래를 실행합니다.

```bash
nohup python3 -u -m vttt.relay_server --bind 0.0.0.0 --port 24040 > relay.log 2>&1 &
echo $! > relay.pid
```

로그는 `tail -n 30 relay.log`로 확인합니다. 백그라운드 서버를 종료할 때는
`cat relay.pid`로 PID를 확인하고, `ps -p 확인한숫자 -o args=`가 이 중계 서버인지 확인한 뒤
`kill 확인한숫자`를 실행합니다. PID 파일만으로 프로세스를 무조건 종료하지 않습니다.

## 4. 기기에서 접속 확인

수정 파일을 반영한 게임기 또는 맥북의 프로젝트 폴더에서 실행합니다.

```bash
python3 -m vttt.relay_server --check 10.255.81.76 --port 24040
```

`VTTT relay OK: 0 room(s)`처럼 나오면 실제 중계 프로토콜로 연결되었습니다.
교체 후에는 HTTP가 아니므로 `curl .../health.txt`로 검사하지 않습니다.

## 5. 두 게임기 실행 및 입장

기본 `configs/runtime.json`에는 `10.255.81.76:24040`이 설정되어 있습니다.
**두 기기 모두** 프로젝트 폴더에서 추가 주소 옵션 없이 실행합니다.

```bash
bash scripts/run_hardware.sh
```

다른 서버에 접속하거나 설정 파일의 주소를 덮어쓰려면 실행 옵션을 지정합니다.

```bash
bash scripts/run_hardware.sh --online-server 10.255.81.76:24040
```

PC 시뮬레이터는 다음과 같습니다. 같은 PC에서 두 개를 실행할 때는 프로필을 분리합니다.

```bash
python3 -m vttt --simulate --online-server 10.255.81.76:24040 --profile runtime/online-host.json
python3 -m vttt --simulate --online-server 10.255.81.76:24040 --profile runtime/online-guest.json
```

1. 각 기기에서 시작 8번 → 메인 메뉴 8번 통신 → 6번 온라인을 선택합니다.
2. 기기 A에서 4번 방 만들기를 선택하고 네 자리 방 번호를 확인합니다.
   방 생성 중에는 `서버 연결 중`과 대상 주소가 표시됩니다. 실패하면 `서버 연결 실패` 화면에서
   8번으로 재시도하거나 1번으로 돌아갑니다. 방 번호가 나온 뒤 `서버 연결 완료 / 상대 입장 대기`가
   표시되면 서버에 연결된 상태이며, 두 번째 기기의 입장을 기다리는 중입니다.
3. 기기 B에서 5번 방 찾기 → 해당 방 선택 → 8번 입장을 선택합니다.
4. 방장이 모드를 선택합니다. 두 기기에서 각각 가위바위보를 선택하면 대국을 시작합니다.
5. 착수한 말이 양쪽 화면에 같은 위치로 나타나는지, 상대 차례 입력이 거부되는지 확인합니다.
6. 5번 길게 누르기로 양쪽 일시정지, 계속하기, 대국 종료와 재대국을 확인합니다.

`configs/runtime.json`의 기본 서버 주소는 다음 두 항목으로 변경할 수 있습니다.
CLI 옵션이 파일의 주소보다 우선합니다. 기존 JSON의 다른 항목은 유지하세요.

```json
"online_host": "10.255.81.76",
"online_port": 24040
```

## 지원 범위와 확인 범위

- 방 검색은 중앙 서버에서 수행하며 UDP 멀티캐스트를 사용하지 않습니다.
- 동시에 최대 64개 방과 160개 TCP 연결을 받습니다. 메시지는 최대 64KiB입니다.
- 앱이 계속 실행 중인 짧은 네트워크 단절은 같은 상대의 식별자로 재접속합니다.
- 두 기기가 모두 끊긴 방은 기본 60초 후 만료됩니다. 서버 재시작 시 방과 대국 복원은 지원하지 않습니다.
- 재시작이나 앱 종료 후에는 두 기기에서 방을 나가 새 방을 생성합니다.
- 방 목록을 선택해 입장하는 방식입니다. 자동 매칭·계정·TLS 암호화·중앙 부정행위 판정은 포함하지 않습니다.
  현재 사설망 개발 테스트를 대상으로 합니다.
- 로컬 실제 TCP 통합 테스트로 방 검색·입장·6개 모드·착수 동기화·재접속·일시정지·재대국·방 격리를 검사합니다.
  실제 서버/라즈베리파이 배포와 LCD/GPIO 조작은 사용 중인 장비에서 최종 확인해야 합니다.

```bash
python3 -m unittest discover -s tests -p 'test_online.py' -v
```
