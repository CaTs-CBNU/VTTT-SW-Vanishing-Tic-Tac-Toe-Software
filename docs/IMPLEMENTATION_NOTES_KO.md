# 구현 내용과 규칙

기준 자료는 업로드된 소스 ZIP과 2026-06-09 1학기 최종발표 PDF입니다. 사용자가 추가로 지정한 두 가지 방침을 적용했습니다.

1. 회로는 PDF와 충돌할 때 **기존 코드의 핀 배치와 입력 극성**을 우선합니다.
2. PDF에 세부 규칙이 없는 추가 모드는 **임시 규칙을 명시하고 구현**합니다.

## 구현한 기능

| PDF의 기능 | 이번 구현 |
|---|---|
| 9개 LCD·9개 버튼 | 기존 GPIO 설정, 공유 SPI/DC/RESET, 개별 CS |
| AI 모델과 앱 통합 | 기존 CNN 가중치 연결, 비동기 AI 계산, 실제 게임판 갱신 |
| 다양한 틱택토 | 배니싱·오리지널·블라인드·그래비티·원스위칭·나인스위칭 |
| 함께 하는 게임 | 기기 한 대에서 2인 교대 대국 |
| 화면 흐름 | 시작 → 메인 → 모드 → 대국 준비 → 대국 → 결과/재대국 |
| 상점 | 가상 코인으로 기존 테마 4종 해금·선택, 실제 결제 없음 |
| 설정 | 상대·AI 난이도·선공·말 수명 표시, 로컬 저장 |
| 튜토리얼 | 조작 설명 + 모드별 규칙 7페이지 |
| 점수 | AI 상대 승/패/무승부, 2인 대국 횟수, 보유 코인 |
| 화면 전환 | 720×720 공통 캔버스, 9개 영역 분할, 변경된 LCD만 갱신 |
| 기기 진단 | 버튼과 LCD 번호 확인 화면 |
| PC 확인 | 동일한 제어·규칙·렌더러를 사용하는 tkinter 시뮬레이터 |

PDF에서 '추후 고려'로 분류한 원격 대전, 서버·DB·소셜 프로필, 틱택토 외 미니게임은 이번 로컬 게임 앱의 범위에 포함하지 않습니다.

## 모드별 명확한 규칙

공통: 선공은 O(내부 값 +1), 후공은 X(-1)이며 가로·세로·대각선 세 칸 연결로 승리합니다. 물리 버튼 번호는 1~9, 내부 행동 번호는 0~8입니다. 유효하지 않은 입력은 착수 횟수나 차례를 바꾸지 않습니다. 기본 200회 착수 제한을 두며 `configs/runtime.json`에서 바꿀 수 있습니다.

| 모드 | 기반 | 이번 동작 | 규칙 상태 |
|---|---|---|---|
| 배니싱 | 각자 말 최대 3개 | 새 말 배치 → 자신의 가장 오래된 말 제거 → 승리 확인 | PDF와 원본 코드 반영 |
| 오리지널 | 일반 틱택토 | 말을 유지하며 세 칸 연결, 판이 가득 차면 무승부 | 기본 틱택토 |
| 블라인드 | 배니싱 | 방금 둔 말 하나만 3초 공개(`blind_reveal_seconds`)하고, 나머지 말은 계속 숨김. 내부 점유·승패는 그대로 유지 | 포스터 반영 |
| 그래비티 | 배니싱 | 누른 칸의 세로줄에서 가장 아래 빈 칸에 말이 떨어짐. 가장 오래된 말이 사라지면 그 위 말들도 아래로 떨어짐. 6번째 수마다 그 수를 두기 직전에 맨 아래줄을 삭제하고(위 말들이 한 줄씩 내려옴) 그다음 말이 놓이므로, 방금 둔 말이 곧바로 지워지지 않음. 9번 칸 아래에 "아래줄 삭제까지 N수"를 표시하며, N이 줄수록 글자가 회색에서 빨간색으로 바뀜 | 포스터 반영 |
| 원스위칭 | 배니싱 | 무작위로 지정된 턴에 예고 시점에 표시된 수명이 같은 내 말과 상대 말끼리만 위치를 바꿈(예: 5·4·7 대 1·6·9라면 5↔1, 4↔6, 7↔9 중 하나). 수명이 가장 짧은 쌍부터 고름 | 포스터 반영 |
| 나인스위칭 | 배니싱 | 무작위로 지정된 턴에 판 위 모든 말의 소유권이 한 번에 반전됨 | 포스터 반영 |

스위칭 턴은 게임 시작 때 4~8수 간격으로 미리 뽑아 `Game.switch_turns`에 저장합니다(`rules.SWITCH_GAP`). 첫 스위칭은 4수 이후라 두 사람 모두 말이 있습니다. 원스위칭은 스위칭 한 턴 전에 가운데 칸에 "다음 수 후 위치 교환!"을 띄우고, 바뀔 두 말을 주황 테두리와 "교환 예정"으로 표시합니다. 교환할 쌍은 다음 수가 어디에 놓이든 같으므로(`Game.switch_pair()`) 예고와 실제 교환이 항상 일치합니다. 교환 쌍은 예고 시점에 화면에 표시된 수명이 같은 말끼리(같은 순서로 둔 말끼리)이며, 수명이 짧은 쌍부터 고릅니다. 다음에 둘 사람의 가장 오래된 말이 그 수로 사라질 예정이면 그 말은 제외합니다. 원스위칭은 교환 때문에 다음 사람이 어떤 수를 둬도 지는 경우(교환 직후 상대 줄 완성, 또는 상대의 바로 다음 수에 승리)를 만들지 않습니다. 그런 쌍이면 다음으로 수명이 같은 쌍을 고르고, 모든 쌍이 그렇다면 그 턴은 교환하지 않습니다(무작위 대국 기준 스위칭 턴의 약 1%). 판정은 한 수 앞까지만 봅니다(`Game.switch_is_fair`). 나인스위칭은 예고 없이, 발생한 순간 가운데 칸에 "위치 교환!" / "소유권 반전!"을 2초 표시합니다. 말의 수명은 말을 따라 이동합니다.

오리지널을 제외한 모든 모드는 배니싱 규칙(각자 말 3개, 4번째 착수 때 가장 오래된 말 제거)을 기본으로 포함합니다.

처리 순서: 착수 → 가장 오래된 말 제거 → (그래비티) 빈 칸 위 말 낙하 → 양쪽 승리 확인(방금 둔 사람 우선) → 스위칭 → 양쪽 승리 확인(방금 둔 사람 우선) → (그래비티) 아래줄 삭제 → 무승부·수 제한 확인. 착수로 이미 이긴 경우 스위칭은 일어나지 않습니다. 나인스위칭과 아래줄 삭제는 새 줄을 만들 수 없고, 원스위칭은 어느 쪽이든 줄을 완성시킬 수 있습니다.

AI는 스위칭 턴 일정을 포함한 내부 상태 전체를 알고 탐색합니다(블라인드와 같은 방식).

블라인드는 숨김 상태에서도 빈 칸에만 둘 수 있습니다. 잘못 누르면 같은 차례에서 다시 시도합니다. 일시정지로 숨겨진 말을 다시 볼 수는 없습니다. 게임이 끝나면 최종 판은 공개됩니다. AI는 내부 상태를 알고 대국하며 이 점은 대국 준비 화면에도 표시합니다.

## AI와 학습 체크포인트

- 원본 `best.pt`는 보존했습니다. 메타데이터는 episode=2500, best_win_rate=0.955입니다. 95.5%는 원본 학습 코드의 랜덤 상대 평가 기록이며 이번 통합 앱의 새 승률 측정값이 아닙니다.
- `runtime_model.npz`는 그 체크포인트의 **같은 CNN 가중치**를 NumPy 배열로 옮긴 것입니다. 모델을 새로 학습하거나 임의 가중치로 바꾸지 않았습니다.
- 추론 구조는 2×3×3 입력, 128채널 합성곱, 잔차 블록 5개, 256차원 완전연결층, Q값 9개입니다. BatchNorm은 평가용 통계로 합성곱에 합쳤고 Dropout은 평가 모드처럼 끕니다.
- 배니싱 대국에서는 CNN의 Q값을 후보 탐색 순서와 동점 수의 우선순위에 사용합니다. 즉시 승리·상대 즉시 승리 허용 여부는 실제 규칙으로 먼저 확인하고, 알파베타 수읽기로 후보를 비교합니다. CNN의 우선순위가 확정 승패를 덮어쓰지 않습니다.
- 다른 모드는 배니싱으로 학습한 가중치를 잘못 적용하지 않도록 **각 모드의 규칙 탐색 AI**를 사용합니다. 원스위칭/나인스위칭도 이동 규칙이 다르므로 해당됩니다.
- 난이도(`vttt/ai.py`의 `LIMITS`, 모드별 설정): 초보·중수·고수는 탐색 깊이/시간과 두 가지 실수 비율(안전한 수 중 무작위, 승리·방어를 무시한 무작위)로 나뉩니다. 고수는 실수 없이 최대 8수 탐색/1.2초입니다. 모드마다 실수 비율을 맞춰 위 난이도가 아래 난이도를 약 80~90% 이깁니다(`python tools/difficulty_match.py --games 150`, 2수 무작위 시작, 150판 기준 82~89%. 판 수가 적으면 ±5%p 정도 흔들립니다). 오리지널은 서로 막기만 해도 비기는 게임이라 난이도 선택 화면 없이 바로 가위바위보로 가며, 항상 중수로 둡니다.
- 착수 간격: AI는 고민 시간과 상관없이 직전 착수 후 2초(`configs/runtime.json`의 `ai_move_seconds`)가 지나야 수를 둡니다. 탐색은 그동안 미리 해 둡니다. 블라인드는 방금 둔 말을 3초 보여준 뒤에 AI가 두므로 약 3초입니다.
- 말 사라짐: 배니싱 규칙으로 사라지는 말은 1초 동안 5프레임(0.2초 간격)에 걸쳐 흐려지며 사라집니다. 이 애니메이션 프레임은 버튼 입력을 버리지 않습니다. 블라인드에서는 숨겨진 말이므로 표시하지 않고, 그래비티는 수를 둘 때마다 ① 새 말과 아래줄 삭제로 내려오는 말이 속도선과 함께 미끄러져 내려오고(0.35초, `Game.drops`), ② 배니싱으로 사라지는 말이 제자리에서 흐려지고(1초), ③ 그 위에 있던 말들이 속도선과 함께 떨어집니다(0.35초, `Game.fell`). 떨어짐은 항상 움직임과 속도선, 사라짐은 제자리 흐림으로 구분됩니다. 규칙상으로는 수를 둔 즉시 떨어진 상태이므로 AI와 승패 판정은 그대로입니다.
- CPU에서 동작합니다. NumPy 모델이 없으면 원본 `.pt`를 PyTorch로 읽는 경로를 시도합니다. 둘 다 사용할 수 없으면 로그에 알리고 규칙 탐색 AI로 계속 대국합니다.

다른 체크포인트로 교체할 때는 동일한 잔차 CNN 구조의 파일을 사용합니다.

```bash
python tools/export_runtime_model.py --source 새_체크포인트.pt

# PyTorch가 설치되어 있으면 두 추론 구현의 수치 일치도 함께 확인
python tools/export_runtime_model.py --source 새_체크포인트.pt --verify
```

내보내기는 원본의 tensor-only ZIP 체크포인트 형식만 제한적으로 읽습니다. 알 수 없는 pickle 클래스·함수는 실행하지 않고 거절합니다. `src2`의 더 작은 DDQN 네트워크와는 구조가 다르므로 그 가중치는 직접 호환되지 않습니다.

## 코드 구조

| 파일 | 책임 |
|---|---|
| `vttt/rules.py` | 6개 규칙, 합법 수, 말 제거·회전, 승패, CNN 상태 표현 |
| `vttt/ai.py` | 즉시 전술 검사, 제한 시간 탐색, 모델 기반 후보 우선순위 |
| `vttt/network.py` | NumPy / 선택적 PyTorch 추론 |
| `vttt/app.py` | 화면 상태, 사람·AI 차례, 일시정지·재대국, 비동기 작업 |
| `vttt/buttons.py` | 디바운스, 짧게/길게 누르기 |
| `vttt/backends.py` | Pi GPIO·LCD / PC tkinter / 테스트 어댑터 |
| `vttt/render.py` | 기존 이미지와 동적 게임 화면을 공통 캔버스로 렌더링 |
| `vttt/profile.py` | 설정·기록·가상 상점 원자적 JSON 저장 |
| `vttt/config.py` | 핀 중복·순서·설정 값 검증 |
| `configs/hardware.json` | 기존 코드 기준 하드웨어 설정 |
| `configs/runtime.json` | 모델·기록 경로와 게임 기본값 |
| `display/app/main.py` | 새 통합 앱으로 연결하는 기존 진입점 |
| `tools/render_previews.py` | 하드웨어 없는 화면 미리보기 생성 |

GPIO/LCD는 메인 스레드에서, 버튼 수집은 입력 스레드에서, AI는 별도 작업 스레드에서 처리합니다. AI 계산에는 현재 보드의 복사본만 전달합니다. 대국을 나가거나 다시 시작하면 이전 작업의 결과를 폐기합니다. 실제 SPI 출력은 순차적이므로 화면 9개의 물리 갱신이 완전히 동시에 일어나는 것은 아닙니다.

기존 `src`, `src2`, 단일 RL 파일의 학습 루프는 별도로 보존했습니다. `src.models`의 import 누락은 보완했지만, 기존 학습 코드에 대한 관점 전환·대칭 증강 등의 앞선 분석을 재학습까지 적용한 버전은 아닙니다. 새 게임 앱은 `vttt`의 공통 규칙과 탐색 코드를 사용합니다.

## 검증과 실제 기기에서 남은 확인

2026-09-09 제작 환경에서 **자동 검증 28개 통과**, `python -m vttt --check`와 기존 진입점의 점검 명령 통과, 14개 화면 미리보기 생성 및 주요 화면 시각 확인을 완료했습니다. 원본 `best.pt`는 SHA-256 비교로 변경되지 않았음을 확인했습니다.

```bash
OPENBLAS_NUM_THREADS=1 python -m unittest discover -s tests -v
python -m vttt --check
python tools/render_previews.py
```

자동 검증은 말 제거와 승리 판정, 입력 무효 처리, 중력 낙하·아래줄 삭제·스위칭·착수 제한, 버튼 디바운스·길게 누르기, 모드 전환, 일시정지, 오래된 AI/버튼 입력 폐기, 블라인드 공개 시간, 결과 중복 방지, 상점 저장을 검사합니다. 기존 체크포인트의 실제 NumPy 추론, 합성곱 기준 계산, BatchNorm 결합 전후 출력도 검사합니다. 모든 모드에서 제어기를 통한 사람 입력과 비동기 AI의 대국 종료를 확인합니다.

하드웨어 어댑터 검증은 GPIO와 ST7789를 모의 객체로 대체하여 공통 RESET 1회, CS 격리, 변경 LCD만 전송, active-low 선택 설정, 화면 재배치, 초기화 실패 시 정리를 확인합니다. 실제 전기 신호·전원·배선·LCD 출력·물리 버튼을 측정한 결과는 아닙니다.

현재 제작 환경에는 Raspberry Pi 하드웨어, PyTorch, 데스크톱 디스플레이 서버가 없습니다. 따라서 실제 기기의 전송 속도와 버튼 반응, tkinter 창의 직접 조작, PyTorch와 NumPy의 직접 출력 비교는 기기에서 추가 확인해야 합니다. UI는 같은 Pillow 렌더러의 `docs/previews/` PNG로 확인했습니다. 미리보기 글꼴은 제작 환경의 한글 대체 글꼴이며 실제 장치에서는 설치한 Noto Sans CJK 또는 운영체제 글꼴이 사용됩니다.

먼저 `--diagnostic`으로 기존 배선과 9개 위치를 확인한 뒤, 배니싱 2인 대국과 AI 대국을 차례로 실행하면 됩니다.
