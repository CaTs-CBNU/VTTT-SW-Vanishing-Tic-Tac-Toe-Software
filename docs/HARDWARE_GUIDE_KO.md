# 다이내믹 틱택토 실행 안내

대상은 기존 Python 코드와 같은 Raspberry Pi 4, 240×240 ST7789 LCD 9개, GPIO 버튼 9개입니다. 핀 번호는 모두 **BCM GPIO 번호**입니다. 사용자의 지시에 따라 PDF 회로도보다 기존 코드를 우선했습니다.

## 1. 설치

압축을 풀고 프로젝트 폴더에서 실행합니다. 런타임은 NumPy로 기존 CNN을 실행하므로 PyTorch 설치나 재학습 없이 시작할 수 있습니다.

```bash
sudo apt update
sudo apt install -y python3-venv python3-pip python3-tk fonts-noto-cjk
python3 -m venv --system-site-packages .venv
source .venv/bin/activate
python -m pip install -r requirements-pi.txt
```

`sudo raspi-config`의 Interface Options에서 SPI를 활성화한 뒤 재부팅합니다. 현재 핀맵은 GPIO 2를 CS, GPIO 14·15를 CS로 사용합니다. 이 배선에서는 해당 핀에 I2C 장치를 함께 연결하지 않고, GPIO 14·15의 시리얼 콘솔/시리얼 기능도 사용하지 않습니다. 이미 동작하던 환경이면 기존 인터페이스 설정을 유지하세요.

## 2. 핀 설정

설정 파일은 `configs/hardware.json`입니다. 화면과 버튼의 논리 번호는 위쪽 왼쪽부터 가로 방향으로 1~9입니다.

| 위치 | 1 | 2 | 3 |
|---|---|---|---|
| 위쪽 행 | 1번 | 2번 | 3번 |
| 가운데 행 | 4번 | 5번 | 6번 |
| 아래쪽 행 | 7번 | 8번 | 9번 |

| 번호 | 버튼 GPIO | 버튼 물리 핀 | LCD CS GPIO | CS 물리 핀 |
|---|---:|---:|---:|---:|
| 1 | 17 | 11 | 2 | 3 |
| 2 | 22 | 15 | 15 | 10 |
| 3 | 5 | 29 | 4 | 7 |
| 4 | 6 | 31 | 12 | 32 |
| 5 | 13 | 33 | 16 | 36 |
| 6 | 19 | 35 | 18 | 12 |
| 7 | 20 | 38 | 14 | 8 |
| 8 | 21 | 40 | 23 | 16 |
| 9 | 26 | 37 | 24 | 18 |

| 공통 신호 | GPIO | 물리 핀 |
|---|---:|---:|
| SCLK | 11 | 23 |
| MOSI / LCD SDA | 10 | 19 |
| DC | 25 | 22 |
| RESET | 27 | 13 |

`button_active_high: true`는 기존 코드의 내부 풀다운 + 누르면 HIGH 방식입니다. 실제 배선이 GND로 눌리는 방식이라면 이 값만 `false`로 바꿉니다. 이 경우 내부 풀업 + 누르면 LOW로 읽습니다. **기본값은 변경하지 않았습니다.**

`rotation`은 물리 LCD 1~9의 각 회전값입니다. 허용값은 0/90/180/270입니다. `screen_order`는 논리 칸 1~9를 어느 물리 LCD로 보낼지 정합니다. 버튼 번호도 화면과 같은 위치를 가리키도록 `button_pins` 배열의 순서를 맞춥니다. 개별 RESET 배선이나 MCP23017 입력은 이번 기본 구성에 포함하지 않습니다.

## 3. 순서대로 실행

```bash
# GPIO를 열지 않고 설정·이미지·CNN 첫 수 계산 확인
python -m vttt --check

# 9개 LCD와 각 버튼 번호 확인
bash scripts/run_hardware.sh --diagnostic

# 실제 게임 실행
bash scripts/run_hardware.sh
```

진단 화면에서 1~9번 버튼을 각각 눌렀을 때 같은 위치의 LCD가 초록색으로 강조되는지 확인합니다. 5번을 1.3초 길게 누르면 설정으로 이동합니다. 시작부터 게임까지 기존 코드의 실행 명령 `python -m display.app.main`도 사용할 수 있습니다.

## 4. 게임 조작

| 화면 | 버튼 / 행동 |
|---|---|
| 시작 | 8번으로 메인 메뉴 진입 |
| 메인 | 2 상점 / 4 점수 / 5 플레이 / 6 설정 / 8 통신 |
| 모드 | 1 돌아가기 / 3 테마 / 4 블라인드 / 5 배니싱 / 6 그래비티 / 7 나인스위칭 / 8 원스위칭 / 9 오리지널 |
| 난이도 선택 | 4 초보 / 5 중수 / 6 고수 / 7 지움 / 8 확인 → 가위바위보 (AI 대국에서 설정의 선공이 켜져 있으면 바로 대국. 오리지널과 2인 대국은 난이도 화면 없음) |
| 설정 | 1 돌아가기 / 4 기본 상대 / 6 말 수명 표시 / 7 선공(AI 대국 전용. 켜짐: 내가 항상 먼저, 꺼짐: 가위바위보. 2인 대국은 항상 가위바위보) / 8 게임 설명 / 9 기기 확인 · 누르는 즉시 저장 |
| 가위바위보 | 7 가위 / 8 바위 / 9 보, 선공 결정 후 게임 |
| 2인 가위바위보 | 기본 상대가 2인 대국일 때. 위 줄(1~3, 뒤집혀 보임)은 2P, 아래 줄(7~9)은 1P. 3·2·1 뒤 "눌러!"와 빨간 테두리가 나오면 1초 안에 선택. 한 명만 누르면 안 누른 쪽이 짐, 비기거나 둘 다 안 누르면 다시. 4 돌아가기 |
| 통신·Wi-Fi | UI 데모 전용. [업데이트 안내](UI_UPDATE_KO.md) 참고 |
| 게임 | 원하는 칸을 눌렀다 떼어 착수. 5번을 1.3초 길게 누르면 일시정지 |
| 일시정지 | 4 메인으로 / 5 계속 / 6 새 대국 / 8 프로그램 종료 |
| 결과 | 4 같은 설정 재대국 / 6 모드 변경 / 7 최종 판 / 8 메인 |

한 번의 길게 누르기가 착수까지 동시에 발생하지 않도록 **짧은 입력은 버튼을 뗄 때 확정**합니다. AI 차례나 화면을 전송하는 중에 눌렀던 오래된 입력은 다음 차례로 넘기지 않습니다. 버튼을 너무 짧게 눌러 인식되지 않으면 0.1초 이상 눌렀다 떼세요. 여러 버튼을 함께 누르면 한 입력만 처리합니다.

블라인드는 착수 후 모든 LCD에 공개 화면을 전송한 시점부터 3초(`blind_reveal_seconds`) 동안 방금 둔 말 하나만 보여줍니다. 공개 중에는 다음 착수를 기다리고, 숨김 화면으로 전환한 뒤 착수합니다. AI도 공개 시간이 끝난 다음 움직입니다. 다른 모드에서 AI는 직전 착수 후 2초(`ai_move_seconds`)가 지나야 둡니다. 블라인드 AI는 내부 보드 상태를 기억하는 방식입니다.

결과는 승리 선을 표시한 뒤 결과 화면으로 전환합니다. 기록과 코인은 프로젝트의 `runtime/profile.json`에 저장됩니다. 이 파일은 지우면 초기화됩니다. 명시적으로 초기화하지 않는 한 유지하세요. 프로그램 종료는 Raspberry Pi 전원을 끄는 동작이 아닙니다.

## 5. PC에서 동일한 게임 확인

Windows는 기본 Python 설치에 tkinter와 맑은 고딕이 있는 환경을 사용합니다.

```powershell
py -m pip install -r requirements-runtime.txt
py -m vttt --simulate
```

Linux는 `python3-tk`, `fonts-noto-cjk` 설치 후 `python -m vttt --simulate`를 실행합니다. macOS는 tkinter가 포함된 Python과 Apple SD Gothic Neo를 사용합니다. 글꼴이 다른 위치에 있으면 `--font /절대경로/한글글꼴.ttf`를 지정합니다.

PC에서는 각 칸을 마우스로 누르거나 숫자 1~9를 사용합니다. Esc는 5번 길게 누르기와 같습니다. PC 시뮬레이터는 GPIO 패키지와 Raspberry Pi를 요구하지 않습니다.

## 6. 화면 속도와 하드웨어 확인

SPI 속도는 기존 코드와 같은 **1 MHz**를 기본값으로 유지했습니다. RGB565 기준 240×240 화면 9개를 전부 보내는 데 필요한 순수 데이터 전송 시간만 약 8.3초이므로 메뉴 전환은 느릴 수 있습니다. 게임 중에는 바뀐 LCD만 전송하고 불필요한 고정 지연을 제거했습니다. 소프트웨어가 만든 공통 프레임도 물리적으로는 LCD에 순차 전송됩니다.

배선 상태가 안정적이면 `baudrate`를 4,000,000 또는 8,000,000으로 올려 진단 화면을 확인할 수 있습니다. 깨짐·색 오류가 발생하면 기존 값으로 복귀합니다. 이 프로젝트에서는 실제 하드웨어에서 높은 속도를 검증하지 않았습니다. 9개 LCD의 전송 시점이 완전히 같은 하드웨어 동기화나 30fps 동영상은 보장하지 않습니다.

RESET은 처음에 전체를 한 번만 리셋하고 HIGH 상태로 계속 유지합니다. 각 ST7789 초기화에는 `rst=None`을 전달해 이미 켜진 다른 LCD를 재리셋하지 않습니다. 화면별 전송 전후 모든 CS를 비활성화하며, GPIO와 SPI 접근은 디스플레이 스레드 한 곳에서 수행합니다. 버튼 입력은 별도 폴링 스레드에서 읽습니다.

| 증상 | 확인할 항목 |
|---|---|
| 버튼이 반대로 동작하거나 인식 안 됨 | `button_active_high`, 실제 버튼 GPIO 순서, 진단 화면 |
| LCD 1·2가 안 나옴 | 기존 코드 기준 CS=GPIO 2·15인지 확인 |
| 두 화면이 같이 바뀜 | CS 배선 중복·단락, `lcd_cs_pins` 설정 |
| 1번 화면이 잠깐 켜졌다 꺼짐 | 공통 RESET 배선, 전원, CS 신호 확인 |
| 이미지가 잘리거나 밀림 | `x_offset`, `y_offset=80`, LCD별 `rotation` |
| 한글이 표시 안 됨 | `fonts-noto-cjk` 설치 또는 `--font` 지정 |
| `ModuleNotFoundError` | 활성화한 가상환경에서 필요한 requirements 설치 |
| 모델 로드 실패 | `--check` 로그와 `runtime_model.npz` 존재 여부. 기본 탐색 AI로도 대국 가능 |
